# 17 · Screen: Text Edit

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/17-screen-text-edit.md`](../zh-CN/specs/17-screen-text-edit.md).

**Status:** Implemented (no undo yet)

This spec delivers an overlay dedicated to refining text after voice input: sentences are shown in large type and the user selects, edits, and appends to them with a gamepad, avoiding the keyboard where possible. It is entered with RB while the composer input is focused (carrying the current draft) and exited with B, which confirms by writing the edited text back and restoring the input's focused state, with no discard path. The overlay is a modal scope with no status-bar title, a blurred (degrading to translucent) background, a microphone icon that lights up while dictating, and blank space below the text so a system touch keyboard never covers it. Sentence segmentation splits on CJK and ASCII sentence punctuation, on commas/dunhao, and on newlines, but never inside quotes, brackets, or backtick code spans, and empty input yields one empty sentence so there is always a focusable dictation anchor. Sentences are focusable and navigated geometrically in all four directions; long-pressing Y inserts dictation after the focused sentence (reusing the spec 16 dictation target), and a blinking caret is drawn at the real selection offset to show where new text will land. X deletes one character backward and repeats when held, aligned with normal text inputs, which replaced the originally specified whole-sentence delete; undo is deliberately not implemented this round. A touch-keyboard fallback lets A edit a single sentence in a native textarea and RB summon the on-screen keyboard via a hidden focusable field, while the composer is given `inputMode="none"` so the keyboard only appears on the text-edit screen. The work lives in `src/renderer/src/textedit/` (`sentences.ts`, `store.ts`, `TextEdit.tsx`) and is verified by `npm run check` (typecheck, zero-warning lint, unit tests) plus an e2e scenario covering RB entry, navigation, X deletion, and B write-back; handheld manual testing and undo remain open.
