# 14 · 界面：任务地图

> 阶段 B · 方向性 spec。

## 目标

按 Back 键打开任务地图，以横向卡片的形式浏览"打开的任务"，并在这里切换、新建、关闭任务，以及打开历史任务。本界面上线后，替换掉 03 的临时任务切换器。

## 依赖

- 11、12。动效见 18。

## 设计方向

### 数据

- **打开的任务**：由本应用维护的一个有序列表，元素是 `SessionRef`（`{ engineId, sessionId }`，见 02 第 5 节），持久化到 `settings.tasks.open`。红点等任务级状态也以 `SessionRef` 为键。
  - **按创建时间从左到右排序**（产品文档要求）。
  - 历史任务被重新打开时，按它原本的创建时间插入到对应位置。
- **历史任务**：底座（v1 即 OpenCode）中存在、但不在打开列表里的会话。
- **红点（未读完成）**：
  - 用户离开某个任务时，如果它还处于 busy 状态，就开始"观察"这个任务；
  - 它变为 idle 时，如果当前工作仍不是它，就标记红点；
  - 用户切回这个任务后清除红点；
  - 红点状态需要持久化，应用重启后保持。
- 首次运行时，打开列表为空。是否自动把最近的 N 个会话加进来？见 P-16。
- **只在地图上关闭，不删除会话**（P-04）：关闭任务只是把它从打开列表里移除，底座里的会话保留，成为历史任务，可以随时重新打开。v1 的界面不删除任何底座会话；`deleteSession` 只在测试和 03 的临时切换器里使用。
- **打开列表是 profile 私有的**：`settings.tasks.open` 和红点状态都存在各自 profile 的设置文件里，所以 04 的稳定版和开发版各有一份，互不影响。这是可以接受的（开发版主要用来预览）。如果以后想让两边一致，可以把这部分状态放到 02 里"会话 → 模型"表所在的共享目录。

### 布局

- 状态栏下方是一排横向卡片。根据屏幕宽度，**同时显示 3 张或 5 张**。
- **中间那张是选中卡片**，比其他卡片大一些。左右切换时整排滑动，带动画（18）。
- 卡片：**白底黑字**，内容是任务标题。通过语义 token `card` / `on-card` 实现（01 的主题与 token 分离），所以以后换整体主题时，卡片的配色可以一起换。
  - 用边框表示状态：当前工作的那张、busy、idle、error 之间要有明显区别。
  - 有未读完成的卡片，右上角显示红点。
- 打开地图时，默认选中当前工作那张卡片。

### 交互（默认键位，均可配置）

| 按键 | 行为 |
|---|---|
| ← / → | 切换选中卡片 |
| A | 把选中的任务设为当前工作，关闭地图 |
| 短按 B | 退出任务地图（P-03）。键盘上"短按 B"和"长按 B"对应的两个动作各绑定独立的键，见 10 |
| 长按 B | 关闭选中的任务，弹出二次确认（12）。只是从地图上关闭，会话保留为历史任务（P-04）。长按时操作提示里有进度环 |
| Y | 新建一张空卡片，放在最右侧（因为它的创建时间最新），并选中它 |
| 空卡片上按 X | 展开历史任务列表（复用 12 的列表输入组件），确认后打开该任务，并直接切到当前工作 |
| 空卡片上按 A | 创建新任务（新建 session），切到当前工作 |
| Back | 同全局的任务地图开关，也可以退出地图 |

退出地图（无论用哪个键）时，如果还有没用过的空卡片，就把它删掉。

- 当前工作那张卡片被关闭后，当前工作切到哪里（P-16）？建议切到相邻的卡片，如果一张都没有了，就进入"新任务"状态。

### 过渡

- 打开地图：当前工作界面缩小，退到背景里，卡片依次入场。
- 选中卡片按 A：选中的卡片放大，变成当前工作界面（共享元素过渡）。细节见 18。

## 验收方向

- 只用手柄完成：打开地图 → 新建任务 → 回到当前工作对话 → 再打开地图切回旧任务 → 长按 B 关闭一个任务（确认）→ 从历史任务中重新打开它，会话内容完整。
- 红点：在任务 A 执行长任务时切到任务 B，A 完成后打开地图，A 有红点；切回 A，红点消失。
- 卡片顺序始终按创建时间排列。
- 退出地图时，空卡片被自动清理。

## 待定输入

P-16：首次运行时是否自动打开最近的任务；关闭当前卡片后切到哪一张。P-03、P-04、P-08 已决定。
