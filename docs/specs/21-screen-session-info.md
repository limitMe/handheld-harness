# 21 · Screen: Session Info

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/21-screen-session-info.md`](../zh-CN/specs/21-screen-session-info.md).

**Status:** Implemented

This spec adds a session-info page on top of Current Work that shows context/cost metrics and lets the user pick a working directory before the session is created and change thinking effort at any time. The page is a fullscreen overlay opened from an INFO status-bar button (no keybinding, Back closes it) and displays message count, provider, model name, context limit, current token usage, context percentage, cost, creation time, and last-activity time. Two directly actionable rows sit at the top: the working directory, editable only while the task is new via the native directory picker and read-only once the session exists, and the thinking effort, chosen from model variants through a `ChoiceDialog` that writes to a pending new session or calls `setSessionEffort` on an existing one. The abstraction layer grows in a backend-agnostic way with `EngineCapabilities.messageUsage`/`modelEffort`/`sessionDirectory`, `SessionSummary.effort`/`directory`, `ChatMessage.usage`, model `contextLimit`/`variants`, and `AgentEngine.setSessionEffort`, and the renderer must branch on capabilities only, never on the backend. Out of scope are charts/reports, mid-session directory migration, and a default-effort setting; per-session directories are fixed at creation (P-22) and efforts persist in a `<key>.efforts.json` file (P-23). Implementation maps the OpenCode SDK v2 fields in `normalize.ts`/`adapter.ts`, adds `app:pickDirectory` and `engine:setSessionEffort` IPC, and adds `SessionInfoPage.tsx`, pure session-info calculations, store pending fields, a fake-engine implementation, and tests. Verification is `npm run check` (398 unit tests) plus new session-info and normalize tests; the INFO button was later changed to a toggle. `session.list({})` turned out to be project-scoped, so a follow-up now lists every known directory, persists directories in `<key>.directories.json`, subscribes to the global event stream, and lets a pending new-task directory be reset to the engine default.

## Custom-directory follow-up (2026-10-21, user report)

- **Symptoms:** after pinning a new task to another working directory, the agent's replies never appeared, and the session could disappear from the list after a refresh.
- **Cause:** `client.event.subscribe` only sees the server's default directory instance, so events from a pinned directory never reached the renderer; `session.list({})` is also project-scoped, so `refreshSessions` dropped custom sessions.
- **Fix:** subscribe to `client.global.event` and unwrap its payload, filtering events to sessions this engine knows about. `refreshSessions`/`refreshPending` list each known directory, session directories persist in `<key>.directories.json`, and an unknown persisted session recovers its directory from the cross-project list on first use. A pending new-task directory now offers "Use default directory".
