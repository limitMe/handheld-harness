# 11 · Focus System

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/11-focus-system.md`](../zh-CN/specs/11-focus-system.md).

**Status:** Implemented

This spec delivers a gamepad-first focus system, modeled on Steam's `Focusable`, that gives every screen a focus tree so it can be operated entirely with a controller while distinguishing the **focused** and **activated** states. In scope are the focus-tree data structure, directional navigation, focus memory, activation, scroll-following, visual style hooks, integration with the input system (spec 10), and adoption on the MVP screen (spec 03); full screen layouts are out of scope and covered by specs 13-17.

Nodes are declared with React components (`FocusContainer`, `Focusable`) but the core logic lives in a pure TypeScript `FocusTree`; directional navigation first searches the current container by its `flow` (row, column, grid or geometric) and then rises to the parent at a boundary, while `memory` containers restore their last focused child and focused, activated and ancestor nodes receive `data-focused`, `data-activated` and `data-focus-within` attributes. Focus changes trigger a padded `scrollIntoView`; A activates a component so it takes over input, B deactivates, and the text input has special rules including a two-stage "up at the first line" exit and hold-Y to activate then start dictation. Modal Base UI overlays push a new focus scope, and focus styles rely on the tree's data attributes rather than `:focus-visible`. Verification is by `FocusTree` unit tests (row/column/grid navigation, cross-container movement, focus memory, transfer on unregister, activation and the two-stage exit) plus e2e keyboard-driven flows that share the same actions as the gamepad; completing spec 03's items 2-6 with a gamepad alone still needs handheld hardware testing. Implementation divergences worth knowing: nodes are registered on existing elements through a `useFocusable` hook instead of wrapping every element, explicit `order` values resolve sibling ordering when nodes mount out of visual order, focus transfer on removal prefers neighbors, and action handlers fire only on press, not on release.
