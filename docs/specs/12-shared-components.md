# 12 · Shared Components: Status Bar, Action Hints, List Input, Dialogs

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/12-shared-components.md`](../zh-CN/specs/12-shared-components.md).

**Status:** Implemented

This spec turns the shared UI pieces into consistent, reusable components: the status bar, action hints, list input, and dialogs with toasts. It builds on Base UI through the `ui/` wrapper (AlertDialog for confirmations, Toast for light messages, Popover/Tooltip positioners for panels anchored next to a component) and applies them across every screen.

The status bar is unified so all screens use it, with an optional title (absent in the text-edit screen), a right-hand group of dictation indicator, network, battery and time, an engine status dot that is hidden when ready, and profile badges only for non-default profiles. Action hints appear next to a focused-and-activated component after a period of no input (default two seconds, configurable or disabled via `settings.hints`), are generated dynamically from the active ActionMap so rebinding updates them automatically, and distinguish short from long presses with a live progress ring; agent permission and question cards reuse the same hints. List input (opened, for example, by LB from the composer) shows engine commands from `engine.listCommands()`, sorted by per-engine recency; confirming inserts the command for the user to send, and known commands route through `runCommand` while other input is sent as a normal prompt. Confirm dialogs are modal with A confirming and B cancelling and default focus on Cancel for destructive actions, and toasts auto-dismiss after a few seconds. Verification covers hint reverse-lookup and rebinding sync, hold-ring rendering, command parsing and recency, confirm-dialog behavior, toasts, settings merging and the `runCommand` engine contract, plus an e2e gamepad flow that selects `/compact`, inserts it and sends it. Notable implementation choices are that no virtualization library was added because command lists are small, hints reuse the Popover positioner without a trigger, `/clear` is handled at the workbench layer rather than the engine, and recent-command history is stored per engine in `localStorage`.
