# 02 · Agent Engine Adapter (OpenCode)

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/02-agent-engine-opencode.md`](../zh-CN/specs/02-agent-engine-opencode.md).

**Status:** Implemented

This spec adds an `AgentEngine` abstraction in the main process with OpenCode as the only v1 implementation, managing the entire server-process lifecycle, normalizing OpenCode's HTTP and SSE interfaces into the application's own types, and exposing them to the renderer over IPC. A contributor should be able to run session creation, prompting, and reply receipt end to end from a single command without opening the UI, and an Electron restart in development must not kill a working agent, which the dogfooding loop depends on. In scope are dependency pinning and binary discovery, three server modes, the engine interface and OpenCode adapter, SSE normalization with reconnect and crash recovery, IPC exposure, an engine debug page, and smoke and event-recording scripts; the chat UI, in-app model and credential configuration, a second engine, and remote servers are out of scope because v1 is local-only. Key decisions include pinning `opencode-ai` and `@opencode-ai/sdk` to the same exact version, and resolving the binary from an environment override, then platform `node_modules` packages, and only then PATH behind an opt-in flag. The three modes are attached (production default, kills the process tree on exit), detached (development default, unref and keep running), and external (manual debugging only), all bound to loopback with a random per-run password and an auto-selected port. Detached servers are reused through a registry file keyed by normalized workspace plus version and deliberately not scoped by profile, so the stable and dev instances share sessions; to avoid killing the separately installed OpenCode desktop app that shares the process name, reuse and shutdown only terminate a pid after confirming it is listening on the registered port. Shared types in `src/shared/engine.ts` define capabilities, `SessionRef`, per-session model selection, and engine events, and engine code must not import Electron so scripts can run in plain Node. The remaining requirements cover IPC channels mirroring the interface, a 30 ms delta-coalescing buffer, exponential-backoff reconnection, crash-restart limits, secret redaction in logs, and an engine-contract test suite that every implementation must pass, alongside smoke, record, and normalization tests.
