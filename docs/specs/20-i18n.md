# 20 · Internationalization (i18n)

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/20-i18n.md`](../zh-CN/specs/20-i18n.md).

**Status:** Implemented

This spec provides a unified multilingual abstraction for the workbench, shipping built-in English and Simplified Chinese copy and a system-menu switch whose choice takes effect immediately, persists across restarts, and follows the OS when set to system. In scope are the language abstraction (the `system`/`en`/`zh` modes, OS-locale resolution, catalog organization, and fallback), a renderer-side `react-i18next` singleton covering all user-visible strings (status bar, current work, task map, system menu, debug pages, dialogs, hints, notifications), the `settings.ui.language` setting with its "Display & hints > Language" row, and unit tests for resolution, catalog-key consistency, and action/context coverage. Out of scope are main-process engine diagnostics (which stay English), engine-returned data such as session titles and model names, and plural/gender localization rules that neither current catalog needs. Core decisions are that catalogs live in `shared` with a `TranslationCatalog` type and depend only on i18next, that the renderer singleton initializes synchronously so tests need no provider, that `useLanguageSync` listens for settings changes and `languagechange`, and that shared English action/context labels are passed as `defaultValue` so a missing key never renders a raw key. The language row is placed in its own group at the end of the Display & hints category to preserve existing navigation order. It is implemented with exact versions of `i18next` and `react-i18next`, and verified by `npm run check` plus e2e specs that force English at launch; handheld CJK layout and live OS-language switching remain to be confirmed.

**Expansion:** the language set is open-ended. In addition to `en` and `zh`, the app ships `zh-Hant` (Traditional Chinese), `ja`, `ko`, `es`, `fr`, `de`, and `ru`, with English as the fallback. Feature work only maintains `en`/`zh`; the remaining catalogs are updated later in a dedicated "i18n alignment" commit and may lag behind (missing keys fall back to English).
