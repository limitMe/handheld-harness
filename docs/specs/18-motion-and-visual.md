# 18 · Motion and Visual System

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/18-motion-and-visual.md`](../zh-CN/specs/18-motion-and-visual.md).

**Status:** Partially implemented (theme system and task-map card motion done; reduced-motion and power-save modes not done)

This spec aims to make the UI feel like a game - natural transitions and clear focus feedback - while holding a steady 60 fps on the handheld's AMD integrated GPU on battery. Its principles are one shared easing curve plus three or four duration tokens, animating only `transform`, `opacity`, and `filter` (never layout properties), treating focus as the most polished motion, and honoring reduced-motion and power-save modes (the latter disabling blur, glow, and background animation). The toolchain is CSS transitions/keyframes for most motion, Base UI data attributes, the Motion package for layout, enter/exit, and springs, and optional Rive or PixiJS for background layers. It also defines the theme mechanism so components use only semantic tokens while concrete values live under `styles/theme/`, with runtime switching via `data-theme`, white-on-black task cards, a minimum 18 px body size, a CJK font fallback order, and a performance budget capping `backdrop-filter` to one layer and allowing message-list virtualization. Acceptance checks that a theme file can be swapped without touching components, that durations are tokenized (no hardcoded values), that reduced-motion collapses animations, and that map/card transitions hold frame rate on the device. What shipped this round is only the theme system (a `system`/`dark`/`light` mode in `settings.ui.theme`, applied to `<html data-theme>` with a light theme file and matching main-process window background) and Motion-based task-map card motion (staggered entrance and a spring-selected scale). The remaining key animations and the in-app reduced-motion and power-save toggles were not implemented, leaving `prefers-reduced-motion` as the global fallback. Verification is `npm run check` plus an e2e case that switches dark/light from the system menu and asserts `data-theme` and settings, with device readability and hand-feel checks still pending.
