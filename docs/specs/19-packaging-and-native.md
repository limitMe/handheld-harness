# 19 · Packaging, Native Helpers, and Device Integration

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/19-packaging-and-native.md`](../zh-CN/specs/19-packaging-and-native.md).

**Status:** Partially implemented (release pipeline and manual/GitHub-Release auto-update done; auto-start, Steam Input, exit confirmation, and native helper processes not done)

This spec covers turning Handheld Harness into an installable, updatable Windows app that launches like a console application, and adding device capabilities the Web APIs cannot reach. The packaging direction is electron-builder NSIS installers (x64, plus arm64 if ARM devices appear), bundling the OpenCode binary as `extraResources` with matching binary-location logic, optional auto-update through electron-updater and GitHub Releases, and an accepted SmartScreen warning without code signing. The native-helper direction is a small separate process (Rust plus gilrs, or SDL3) reading XInput/Windows.Gaming.Input and forwarding events to the main process as an input source parallel to the Gamepad API, needed for background input, the Guide key, richer rumble, and Steam Overlay; its build requires local toolchains and ships as a prebuilt binary. Device integration covers boot-to-app autostart in fullscreen, a Steam Input template so Steam only passes through XInput, battery-based power-save, a `haptics.pulse(kind)` wrapper for long-press/send/authorization/task-complete, and an exit confirmation when tasks are in progress. What was actually delivered is release basics plus update: an `electron-builder.yml` NSIS config, a release default workspace of the OS Documents directory, packaged binary lookup under `process.resourcesPath`, a `npm run dist` script, and a manual (About-page) update flow that fetches GitHub Releases release notes, downloads, and offers restart/later, published with `--publish always` to the public `limitMe/handheld-harness` repo with no embedded token. Auto-start, Steam Input, exit confirmation, native helpers, and the remaining `P-19` items are not done, and since the implementing agent did not run `npm install` or packaging, packaging and end-to-end update behavior require the user to verify with `npm run dist` and `npm run dist:publish`.
