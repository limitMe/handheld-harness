# 03 · 最小可用工作台

## 目标

在 02 的引擎之上做一个**能用来干活**的最小 UI：

- 在掌机上能用键盘、触屏，以及 Win+H 语音输入与 Agent 对话；
- 能处理授权请求和提问；
- 能在多个任务之间切换。

本 spec 的布局方向与产品文档里的"当前工作"界面一致，但只做最小版本。粘滞折叠、输入框收起、手柄操作等留给阶段 B（13 等）。

做完本 spec 后，就具备了 spec 04 自举开发所需的全部 UI 能力。

## 范围

- **包含**：
  - 渲染进程状态管理；
  - 聊天列表：Markdown、工具调用、流式输出；
  - 输入框；
  - 授权请求卡片和提问卡片；
  - 中止任务；
  - 临时的任务切换器；
  - 状态栏标题；
  - 错误横幅；
  - 字号缩放；
  - Fake 引擎；
  - 单元测试和 e2e 测试。
- **不包含**：
  - 手柄和焦点系统（10、11）；
  - 粘滞折叠、输入框收起和展开（13）；
  - 任务地图（14）；
  - 系统菜单（15）；
  - 应用内语音（16）；
  - 列表输入、操作提示（12）；
  - 动效打磨（18）。

## 依赖

- spec 02 已通过验收。

## 设计

### 1. 状态管理（必须）

- 使用 zustand。store 按切片划分：
  - `engines`：按 engineId 保存 status 和 capabilities；
  - `sessions`、`messages`（懒加载）、`pending`（permissions 和 questions）：都以 `SessionRef` 为键，序列化为 `engineId:sessionId` 字符串；
  - `ui`：当前会话（`SessionRef`）、草稿等。
- v1 只有一个引擎，但不得把 engineId 写死在 UI 里。
- 所有引擎事件都经过一个**纯函数** `applyEngineEvent(state, event) => state`（放在 `src/renderer/src/state/`），并对它做单元测试。
- **启动和重连**：收到 `engine.status: ready` 时，重新拉取 `snapshot()`，并重新加载当前会话的 `getMessages()`。
- 打开哪个会话：
  1. 优先打开 `settings.ui.lastSession`（新增设置字段，类型是 `SessionRef`），前提是这个会话还存在；
  2. 否则进入"新任务"状态。
- **不要预先创建空会话**。只有在新任务里发送第一条消息时才调用 `createSession()`。
- 每个会话的草稿只保存在内存里：切换会话时保留，重启应用后丢失。

### 2. 布局（必须）

- 所有对话框、浮层和按钮都通过 `ui/` 包装层使用 Base UI（01 第 6 节），包括删除确认、临时任务切换器、授权卡片里的按钮。确认类对话框用 Base UI 的 AlertDialog 包装；需要新包装时在 `ui/` 中新增。

```
┌──────────────── StatusBar：标题 = 当前任务标题 / "新任务" ───── ● 🔋 14:32 ┐
│                                                                        │
│  [Agent 消息，靠左]                                                    │
│                                         [用户消息，靠右，限制最大宽度] │
│  [工具调用标签 ▸ bash: node -v ✓]                                      │
│  [Agent 消息 ……]                                                       │
│  ── 授权请求卡片 / 提问卡片（如果有）──                                │
│  ⋯ Agent 正在工作（busy 时显示）                                      │
├────────────────────────────────────────────────────────────────────────┤
│  [ 多行输入框                                    ] [发送 / 停止]       │
└────────────────────────────────────────────────────────────────────────┘
```

- 用户消息靠右，Agent 消息靠左，与产品文档一致。
- 消息列表：
  - 已经在底部时，有新内容就自动滚到底；
  - 用户往上翻时停止自动滚动，并显示"↓ 最新"按钮。
- 长会话的性能：每条消息容器加上 `content-visibility: auto`。本 spec 不要求做虚拟列表。

### 3. 消息渲染（必须）

- **文本**：用 react-markdown + remark-gfm 渲染。代码块用 rehype-highlight，可以横向滚动。
- **链接**：点击后通过 IPC 交给主进程用 `shell.openExternal` 打开，主进程只放行 http 和 https。
- **流式输出**：正在流式输出的 text part，Markdown 最多每 50 ms 重新渲染一次，避免卡顿。
- **工具调用**：
  - 显示为一行标签：图标、工具名、title 或 inputSummary、状态（等待中 / 运行中 / ✓ / ✗）。
  - 点击或按 Enter 展开输出，展开区最大高度为屏幕的 40%，内部可滚动。
- **reasoning**：显示为一个折叠的"思考"标签，可以展开。
- **other**：显示为一个灰色小标签，内容为 `rawType`。
- **Assistant 消息的脚注**：模型名、耗时、错误信息（如果有）。
- **能力降级**：所有按引擎能力隐藏或降级的行为，都只读 `capabilities`，不得判断引擎类型（见 02 第 9 节）。例如 `streamingDeltas` 为 false 时，消息一次性出现，busy 指示照常显示。

### 4. 输入框（必须）

- **必须用原生 `<textarea>`**，不要用 contenteditable 或自绘输入框。原因：
  - Win+H 语音输入和 Windows 触屏键盘都依赖原生文本控件；
  - spec 16 的"插入到光标位置"会用到 `selectionStart` 和 `selectionEnd`。
- 高度随内容增长，最多占屏幕的 40%。
- `Enter` 发送，`Shift+Enter` 换行。输入法正在组字时（`isComposing`）按 Enter 不发送。
- 会话 busy 时：
  - 发送按钮变成"停止"；
  - 可以继续输入，但不能发送；
  - `Esc` 中止当前会话。
- 首次进入和切换会话后，输入框自动获得焦点。

### 5. 授权请求与提问（必须，最小实现）

本节是自举阶段的最小版本。正式交互按 P-02 的决定，在 13 里改为复用操作提示：卡片出现时自动聚焦，旁边显示可用按键。

- 当前会话有待处理的权限请求时，在消息列表底部显示卡片，内容为 title、kind、patterns，以及三个按钮：**允许一次 / 始终允许 / 拒绝**。引擎能力 `permissionAlways` 为 false 时，隐藏"始终允许"按钮。
- 键盘：
  - 卡片出现时，如果输入框是空的，焦点自动移到卡片上；
  - 卡片获得焦点后，`1` / `2` / `3` 对应三个按钮，`Tab` 可以在卡片和输入框之间切换。
- 提问卡片：
  - 每个问题列出选项按钮，按问题的 `multiple` 决定单选还是多选；
  - 卡片上还有"提交"和"忽略"两个按钮，"忽略"调用 `rejectQuestion`。
- 其他会话的待处理请求，在任务切换器里用 ⚠ 标记。

### 6. 临时任务切换器（必须，spec 14 完成后移除）

- `Ctrl+K` 打开一个浮层列表，列出全部会话，按 `updatedAt` 倒序。每一行显示：标题、相对时间、运行状态（busy 时有动态指示）、⚠ 待处理标记。
- 支持输入文字过滤，`↑` / `↓` 选择，`Enter` 切换，`Esc` 关闭。
- `Ctrl+N`：进入"新任务"状态。
- `Ctrl+Shift+Backspace`：删除当前会话，需要二次确认。这是本临时切换器独有的清理手段，14 的任务地图不会删除底座会话（P-04）。

### 7. 其他（必须）

- **状态栏标题**：当前会话的 title。没有会话时显示"新任务"。
- **错误横幅**：
  - 引擎 `down` 时，在顶部显示错误信息和 hint；
  - `reconnecting` 时显示"正在重连…"；
  - 恢复后自动消失。
- **字号缩放**：`Ctrl+=`、`Ctrl+-`、`Ctrl+0`，通过 `webContents.setZoomFactor` 实现，范围 0.8–2.0，持久化到 `settings.ui.zoom`。
- **触屏可用**：每个可交互元素的点击区域 ≥ 44×44 px。所有功能都能只用触屏完成。
- **引擎配置透传**：用 02 提供的 `HANDHELD_OPENCODE_CONFIG_CONTENT` 环境变量，在测试和验收时调整权限策略。

### 8. Fake 引擎（必须）

- 增加 `HANDHELD_ENGINE_MODE=fake`，在主进程里实现一个 `FakeEngine`，实现完整的 `AgentEngine` 接口，不需要网络和凭据。它必须通过 02 的引擎契约测试。
- 可以用 `HANDHELD_FAKE_CAPABILITIES`（例如 `streamingDeltas=false,permissionAlways=false`）关掉部分能力，用来验证 UI 的降级是否正确，也为将来接入能力较弱的底座做准备。
- 对 `prompt` 的回应：
  - 默认按脚本回放 `tests/fixtures/opencode/1.18.34/` 中的事件，事件经过与真实引擎相同的 `normalize`；
  - 消息文本以 `/fake ` 开头时，进入特殊场景：
    - `long`：流式输出约 3000 字的 Markdown，带代码块；
    - `permission`：触发授权请求；
    - `question`：触发提问；
    - `error`：模拟会话出错；
    - `many`：一次性生成 200 条历史消息。
- Fake 引擎用于 e2e 测试和阶段 B 的 UI 开发，**不得**在构建产物里默认启用。

### 9. 测试（必须）

- **单元测试**：
  - `applyEngineEvent`：delta 拼接、part 的 upsert、会话状态变化、权限请求的出现和消失、对未知会话的事件做容错；
  - 输入框在输入法组字时按 Enter 不发送；
  - 链接白名单。
- **e2e 测试**（`HANDHELD_ENGINE_MODE=fake`）：
  1. 发送一条消息，看到回放的回复；
  2. `/fake permission` 出现卡片，点"允许一次"后卡片消失；
  3. `Ctrl+N` 新建任务后发送消息，再用 `Ctrl+K` 切回第一个任务，内容仍在；
  4. `Ctrl+R` 重新加载后仍在同一个任务。
  5. 用 `HANDHELD_FAKE_CAPABILITIES=permissionAlways=false` 启动后发送 `/fake permission`，卡片上没有"始终允许"按钮。
- 同时把 01 的 `tests/e2e/smoke.spec.ts` 改为使用 `HANDHELD_ENGINE_MODE=fake` 启动，这样 e2e 不会去拉起真实的 OpenCode server，也不依赖工作区配置。

## 验收标准

除第 1 条外，都在掌机上用**真实引擎**（`npm run dev`）验证。

| # | 标准 | 验证方法 |
|---|---|---|
| 1 | 自动化测试 | `npm run check` 和 `npm run test:e2e` 都通过 |
| 2 | 基本对话 | 输入"列出当前仓库根目录的文件"后，流式显示回复，出现工具调用标签并完成，最后的列表以 Markdown 渲染 |
| 3 | 授权请求 | 用 `$env:HANDHELD_OPENCODE_CONFIG_CONTENT='{"permission":{"bash":"ask"}}'` 启动（键名以锁定版本为准），让 Agent 运行 `node -v`：出现授权卡片；点"允许一次"后命令执行；再试一次点"拒绝"，Agent 能收到拒绝 |
| 4 | 中止 | 让 Agent "从 1 数到 300，每行一个数字"，输出过程中按 Esc，会话停止，状态回到 idle |
| 5 | 多任务并行 | 任务 A 在执行长任务时，按 Ctrl+N 建任务 B 并对话；Ctrl+K 切回 A，A 的内容是最新的，并且一直在继续 |
| 6 | 重新加载 | 按 Ctrl+R 后回到同一个任务，历史完整 |
| 7 | 重启后恢复 | 任务 busy 时关闭应用，等 30 秒后再 `npm run dev`，任务已经在后台完成，内容完整（依赖 detached 模式） |
| 8 | 语音输入 | 光标在输入框里时按 Win+H，口述一句中英混合的话，文字插入到光标处，然后可以发送 |
| 9 | 只用触屏 | 拔掉键鼠后，用触屏加系统触屏键盘完成：发送、处理授权、切换任务、停止 |
| 10 | 链接 | 点击回复中的 https 链接，在系统默认浏览器中打开 |
| 11 | 引擎故障 | 执行 `Stop-Process -Name opencode -Force`，出现"正在重连"横幅，恢复后横幅消失，当前会话内容正确 |
| 12 | 流式性能 | `HANDHELD_ENGINE_MODE=fake` 下发送 `/fake long`，流式输出期间在输入框打字没有明显卡顿 |
| 13 | 字号 | 按 Ctrl+= 放大，重启后放大比例保持不变 |

## 待定输入

- 无。P-02 的正式交互在 13 里做；P-08 已决定：沿用 01 的默认主题，只使用语义 token。

## 给实现 Agent 的注意事项

- 这是自举阶段的最后一块 UI。**稳定和可用优先于好看**，不要提前实现阶段 B 的动画和焦点系统。
- 所有新增的设置字段都要加进 settings 的 zod schema，并提供默认值。
- 渲染进程只通过 `window.handheld.engine` 访问引擎。
