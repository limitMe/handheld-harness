# 10 · Input System and Key Mapping

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/10-input-system.md`](../zh-CN/specs/10-input-system.md).

**Status:** Implemented

This directional stage B spec turns raw gamepad and keyboard input into semantic Actions dispatched according to the current screen and component, with every binding remappable. It covers gamepad polling, input normalization with dead zones, short and long presses, and repeat, keyboard mapping, the ActionMap data format, layered configuration, a context stack with event dispatch, and capture-next-control remapping. Its scope excludes the focus tree, the key-binding settings UI, and a native helper process, which are handled by later specs. The pipeline normalizes raw input, resolves it through the action map for the active context, and passes the resulting action down a context stack from the top, stopping once handled. Controls use a unified naming scheme while Guide is left unmapped because the system consumes it, and a key bound to both short and long press defers its decision until release or the 400 ms threshold. Keyboard input goes to a focused text field except for combinations marked global. Actions are defined in a shared file, and configuration layers defaults, device presets matched by gamepad id, and user settings, with conflict detection after merging. The spec also weighs driving Base UI components either through controlled properties or by converting gamepad actions into trusted keyboard events via `sendInputEvent`, recommending a mix and validating it with a prototype. Acceptance expects pure TypeScript logic tested with simulated time series, gamepad-only operation verified together with the focus spec, live effect of settings changes without restart, and an action column in the gamepad debug page; known risks are Steam Input, vendor desktop modes, Game Bar, and losing input when the window is unfocused. The implementation record notes the delivered modules, English action labels, the resolved pending decisions, and follow-up tuning done after handheld testing.
