# 16 · Voice Input Protocol and Implementation

> **English summary.** The full spec is in Chinese: [`docs/zh-CN/specs/16-voice-input.md`](../zh-CN/specs/16-voice-input.md).

**Status:** Partially implemented (protocol layer and Doubao adapter done; offline fallback not done)

This spec defines a provider-agnostic speech-recognition protocol and its implementation so the app can swap speech providers, insert live dictation at the active cursor via hold-Y, reuse the same capability from the text-edit screen, and optionally fall back to an offline model. The protocol lives in `src/shared/speech.ts` (`SpeechProviderInfo`, `SpeechSessionOptions`, `SpeechEvent`, `SpeechProvider` with start/pushAudio/stop/cancel), with a scripted `MockSpeechProvider` reserved for tests only.

The design layers microphone capture in the renderer (16 kHz mono PCM via getUserMedia and an AudioWorklet, sent over IPC), a main-process `SpeechService` that selects a provider and routes `started`/`partial`/`final`/`level`/`error`/`ended` events, and a renderer `DictationController` that writes text into the target field and drives the status-bar indicator; API keys and network access stay in the main process, and credentials are encrypted with Electron's `safeStorage` in a per-profile file rather than `settings.json`. Dictation records the target and selection on start, deletes the selection, previews replaceable partials, commits finals and advances the cursor, ends on cursor move or focus change, and rolls back on cancel (B); hold-Y only starts when the composer or the text editor is the target, with a short microphone preheat so the first word is not clipped. The first phase delivered the protocol, the main-process service, a Doubao (Volcengine Seed-ASR streaming) adapter, encrypted credentials and a debug page; the second wired up hold-Y dictation, the editor/controller state machine, the status-bar indicator and the voice settings page; a third added Fun-ASR (DashScope) and OpenAI realtime providers plus a 16 kHz to 24 kHz resampler. Verification covers the protocol codecs, the speech service, the dictation editor/controller, per-provider credential isolation and the build's AudioWorklet artifact, with handheld testing still recommended. The offline fallback (sherpa-onnx) is not implemented, so a disconnection only produces a failure toast and no automatic provider switch.
